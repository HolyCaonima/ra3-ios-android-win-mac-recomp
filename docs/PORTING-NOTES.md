# 移植中的工程经验

以下只总结可复用的设计问题，不含游戏地址、函数片段、生成规则、真实测试字节或上游补丁。

## 线程状态和同步

把频繁访问的客体状态集中存放，可以减少某些平台上的重复 TLS 寻址。但“改变存储布局”仍会影响状态交换、回调和线程隔离，必须覆盖跨函数和跨线程场景。

锁释放时通知实际等待者，可以降低无用唤醒；需要保持递归次数、所有权和失败行为。减少条件变量广播不等于重写调度模型，也不能证明整个程序没有竞态。

ARM64 上实现少量未对齐原子的回退，并不意味着所有普通读写都满足 x86 内存顺序。完整语义还涉及浮点、SIMD、批量访存和不同共享路径；这是目前的公开限制之一。

## 非局部控制流

仅恢复客体寄存器和栈指针，不足以正确实现跨层的非局部跳转。宿主调用栈也必须抵达匹配的恢复位置。直接调用和经过导入跳板的调用都需要检查，不能只覆盖其中一种。

## 图形资源寿命

“CPU 不再使用”与“GPU 已经完成”是不同事件。资源回收、驻留集合、延迟命令编码和提交完成之间必须有明确所有权。等待中的渲染线程可能只是 GPU 故障的后果，不能仅凭等待栈认定为 CPU 锁死。

平台验证器报告的具体错误应分别处理。例如顶点步长的静态/动态契约与异步命令仍引用已释放 buffer 是不同问题。修复其中一个后仍要观察另一个；一轮复测通过不等于所有旧故障都有同一个根因。

## 输入与呈现

触摸坐标需要沿实际呈现链逆向换算：窗口坐标、黑边、目标区域、源区域和客体桌面坐标。只按屏幕宽高缩放，在游戏内改变分辨率后可能失效。按下和释放必须使用一致的按钮状态，拖出画面和系统取消也要完成释放。

## 网络与可观察结果

发现服务只说明存在兼容端点，不能直接当成房间、授权成功或对局成功。兼容层需要报告真实的系统发送结果。平台权限、实际网卡地址和路由分别验证，弹出权限对话框并不证明网络路径可用。

公开版仅记录发现层面的工程经验，不提供游戏网络包、授权逻辑或服务替代实现。

## 构建与诊断

开发构建应保留可代表实际执行路径的优化，同时提供符号。发布构建与开发构建的标记需清楚，诊断开关应独立控制。不能用开启重度 GPU 校验的帧率代表常规性能。

本仓库 `cmake/` 只统一 CMake 配置选择和元数据输出；它不负责签名、分发、优化参数、游戏版本选择或平台打包。
