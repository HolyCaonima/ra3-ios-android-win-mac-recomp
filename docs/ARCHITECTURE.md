# 系统分层

本文描述开发路线的大体结构。完整实现未在本次公开版本中提供；本仓库能运行的内容以根 README 清单为准。

## 静态翻译与客体状态

静态翻译将已经确认的机器指令语义表示成宿主编译器可处理的 C。生成源码仍然可能包含原程序的表达和数据，因此它属于本地开发材料，不因扩展名变成 `.c` 就适合发布。

运行时需要明确表示整数寄存器、标志位、浮点/SIMD 状态、客体栈和地址空间。客体指针不能直接当成 64 位宿主指针。地址转换、宽度、对齐、越界和生命周期必须在统一边界处理。

翻译函数调用既包含静态可知的调用，也包含间接目标。未知目标需要留下可诊断的失败，而不是返回任意默认值继续执行。异常恢复和非局部跳转还必须同时恢复客体状态与宿主控制流。

## 兼容层

兼容层连接客体所依赖的操作系统接口与宿主能力：文件、内存、线程、同步、时间、窗口、音频和网络。每个入口都需要准确的参数宽度、调用约定、结构体布局、返回值和错误语义。

可选功能在接口规定允许时返回明确的“不支持”，由调用方选择回退；未知签名、未知栈行为和核心操作缺失应停止。伪造成功会把缺失实现变成更难定位的后续故障。

资源输入与可写输出分离。原始输入只读；用户档案、日志、缓存和临时文件写入各平台允许的独立目录。路径映射既要考虑字符串，也要考虑盘符枚举、大小写和资源查找行为。

## 图形与宿主

研究中的图形路线包含 D3D9 接口桥与后端适配。Android 方向使用 Vulkan；Apple 方向涉及 DXVK、MoltenVK 与 Metal。早期自写图形后端属于探索记录，不代表已经覆盖所有 D3D9 行为。

图形桥负责客体对象和宿主对象之间的边界，后端负责资源、管线和命令，宿主负责窗口、surface、呈现及生命周期。命令提交完成前，任何被 GPU 引用的底层资源都必须保持有效。

平台宿主还管理事件循环、键鼠/触摸/笔输入、音频设备和后台切换。Apple 窗口/UI 操作与游戏工作线程之间需要明确的线程归属；主线程持续处理事件，不能简单等待游戏线程退出。

## 本次公开工具的位置

构建配置模块用于统一开发/发布配置标记，图像工具用于观测差异，发布检查用于控制公开内容。它们都处于外围工程层，不包含上述翻译、兼容层或游戏实现。
